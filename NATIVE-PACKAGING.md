# Native packaging evaluation — PaddleBai

Tauri 2 Windows packaging is now configured in `src-tauri/` with bundled `out/`, official-logo icons, an NSIS offline-WebView2 installer and native backup saving. Rust/Cargo and MSVC are unavailable here, so no executable/installer has been generated or tested. Android/iOS remain browser PWAs for device testing; no native mobile package is configured. See [INSTALL-AND-TEST.md](INSTALL-AND-TEST.md) for the implementation and commands.

## Windows / Tauri

Bundle `out/` as the frontend; do not run a Next.js server or rely on the PWA cache for native startup. Build with Rust and Visual Studio C++ build tools. Generate Windows icons from the preserved `public/icons/logo.png`. NSIS can produce an `.exe` installer. Windows needs WebView2; configure `webviewInstallMode: { "type": "offlineInstaller" }` to include its installer for disconnected machines, rather than a downloader. This increases installer size. Evaluate a fixed runtime if deployments require a pinned WebView2. Verify fresh installation without networking and without a preinstalled runtime. See [Tauri prerequisites](https://v2.tauri.app/start/prerequisites/) and [Windows distribution](https://v2.tauri.app/distribute/windows-installer/).

Implemented Windows persistence: the existing Dexie/IndexedDB adapter in a separate persistent WebView2 app profile. The identifier and HTTPS scheme stay stable; browser data must be transferred by backup import. Browser/PWA service workers are bypassed in Tauri because the whole frontend is bundled. Native Save dialog plus filesystem writing handles desktop backup export. No SQLite adapter has been added. A future alternative is a separate native repository using SQLite in the app data directory, accessed through Rust commands that own whole transactions. Tauri's [SQL plugin](https://v2.tauri.app/plugin/sql/) supports SQLite and migration registration. Avoid implementing multi-statement domain transactions as unrelated JavaScript calls. Store photo blobs in SQLite initially so photos, records, and restore snapshots can commit atomically. Restrict file/dialog permissions to user-selected backup paths.

The browser's `paddle-na-bai` IndexedDB is not automatically accessible to the native origin. Move data using the versioned backup: validate, migrate to SQL tables, preserve UUIDs/timestamps/attendance/eligibility, import photos, and commit once. Maintain a SQL migration ledger separate from Dexie versions. Native backup export must produce the same portable format, not a raw platform-specific database. Test upgrade, rollback, multi-window locking, disk-full handling, and abrupt process exit on Windows before shipping.

## Android / iOS / Capacitor

Use `webDir: "out"` and bundle all assets; do not configure a remote production `server.url`. Disable web service-worker registration inside a future native adapter. Android needs Android Studio, SDK and the matching JDK; iOS needs macOS, Xcode, signing/provisioning and device validation. The current Capacitor 8 guide specifies Node 22+, Xcode 26+, and Android Studio 2025.2.1+. Pin compatible versions when implementation begins. See [environment setup](https://capacitorjs.com/docs/getting-started/environment-setup).

Recommended persistence: a separate mobile repository using a maintained SQLite plugin, native transactions and its own migration ledger. Evaluate plugin maintenance, licensing and supported OS versions before selection. Use [Preferences](https://capacitorjs.com/docs/apis/preferences) for small settings only; it is not a relational database. Browser IndexedDB and mobile SQLite do not share their adapters or storage locations. Import existing browser backups explicitly, preserving identifiers and timestamps. Use database photo blobs initially for atomic restoration; if files are used instead, stage them, commit metadata after successful file writes, and recover or clean up orphan staging files after crashes.

Use [Camera](https://capacitorjs.com/docs/apis/camera) or the system picker for photo selection with required permissions. Validate size, type, decode and dimensions before persistent storage; copy temporary URIs into app-owned storage. Create backups with [Filesystem](https://capacitorjs.com/docs/apis/filesystem) and share through [Share](https://capacitorjs.com/docs/apis/share), with Android FileProvider paths and iOS privacy declarations configured. Native restore needs a document picker and the same preview/confirmation/atomic replacement semantics. App uninstall can remove local data; shared backups need a separate safe destination.

Physical-device and compiled-native acceptance work remains: physical Android/iOS offline cold start, permission denial, picker cancellation, photo lifetime, sharing, database upgrades, process termination, low storage, installer/signing, and device-specific accessibility. No native platform test claims are made.
